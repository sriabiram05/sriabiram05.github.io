01 — About

Engineering From
First Principles

I'm a Computer Systems Engineering undergraduate at SLIIT (2023–2027), specialising in the intersection where hardware meets software — where the physics of circuits and the logic of code combine to produce systems that actually work in the real world.

My approach is empirical. I design in simulation, fabricate in hardware, test against measurable targets, and document every failure. The cache simulator taught me what 64B line sizes do to spatial locality. The PID motor taught me why derivative terms amplify noise. The UAV taught me that five crashes can teach more than five textbooks.

I'm targeting roles in embedded firmware, control systems, robotics, and IoT engineering — environments where I can apply rapid prototyping and systems-level thinking to real engineering challenges.

// Systems Thinking

Every component is part of a larger system. I design with interfaces, constraints, and failure modes in mind from the start.

// Fail → Analyse → Rebuild

Iterative failure is the fastest path to robust systems. I document what broke, why it broke, and what the fix teaches me architecturally.

04 — Methodology

How I Engineer Systems

A repeatable process applied to every hardware-software system I build.

01
Problem Analysis
Define performance targets and constraints before touching hardware or code.
02
System Design
Architecture the hardware-software interface, data flow, and control logic.
03
Simulation
MATLAB/Simulink or Python sim to validate design before committing to hardware.
04
Prototype
Build minimal viable hardware. Register-level firmware. Measure immediately.
05
Testing
Run every scenario. Capture data. Compare against the target spec.
06
Failure Analysis
When something fails, find the root cause before changing anything.
07
Optimisation
Refine based on evidence — not intuition. PCBs over breadboards. PI over PID where justified.
08
Validation
Final end-to-end test against original spec. Document results. Ship.

05 — Personal Project

AGNI WING

A self-directed, five-person engineering team on a long-term mission to build an autonomous fixed-wing UAV. We started by learning to fly manually.

The Mission

Long-term goal: autonomous fixed-wing UAV. Immediate goal: understand aerodynamics through failure. We chose to build and fly before simulating in XFLR5/OpenVSP, because real crashes teach things that virtual models don't.

The 6-day initial build cycle covered aerodynamic layout, fuselage sizing, CG calculation, propeller offset, thrust-line alignment, and wing-fuselage integration — using NASA Glenn interactive simulations for airfoil analysis and CAD for dimensional work.

// FLIGHT TEST PROGRAMME — 5 ATTEMPTS

ATTEMPT 01
💥
No Liftoff
CG too far aft. Nose pitch-up immediately on thrust. Structural failure on landing.
ATTEMPT 02
💥
Partial Lift
CG corrected. Insufficient thrust-to-weight margin. Settled back after 1–2 sec. Propeller damage.
ATTEMPT 03
💥
Roll Instability
Improved T/W. Lateral instability from propeller offset. Rolled right and crashed within 3 sec.
ATTEMPT 04
⚠️
Wing Root Failure
Offset corrected. Airframe achieved brief climb. Wing root structural failure under aerodynamic load.
ATTEMPT 05
✅
First Flight
All corrections applied. ~12 sec sustained flight. 30–40 ft altitude. Unstable descent but controlled.
